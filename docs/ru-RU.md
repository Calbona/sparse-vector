# sparse-vector

Разреженный вектор: отображение целых индексов в произвольные значения, в котором хранятся только позиции, отличные от значения по умолчанию

## Идея

Индексы могут быть отрицательными, и они не обязаны быть последовательными

Поэтому вектор всего с тремя элементами занимает всего три элемента — независимо от того, равны эти три индекса `0, 1, 2` или `-10^9, 0, 10^9`

Эта библиотека намеренно **не** является вектором в математическом смысле. Она не несёт никакой арифметики: это структура данных, и только она

## Реализации

Один и тот же тип предлагается на трёх языках. Все правила ниже у них общие — различается только написание

| Язык | Пакет | Версия | Каталог | Статус |
| --- | --- | --- | --- | --- |
| TypeScript | `@calbona/sparse-vector` | 1.0.2 | [`typescript/`](../typescript/) | выпущено |
| C++ | `sparse-vector` | 1.0.0 | [`c++/`](../c++/) | выпущено |
| Rust | `sparse-vector-rs` | 1.0.0 | [`rust/`](../rust/) | выпущено |

Каждый пакет нумеруется независимо, поэтому номера различаются. Сейчас все три реализуют одну и ту же семантику

## Установка

**TypeScript**

```sh
npm install @calbona/sparse-vector
```

**C++** — пока не выпущена в vcpkg или Conan. Два заголовочных файла и нечего компоновать, поэтому достаточно указать CMake на репозиторий:

```cmake
include(FetchContent)

FetchContent_Declare(sparse-vector
  GIT_REPOSITORY https://github.com/Calbona/sparse-vector
  GIT_TAG main
  SOURCE_SUBDIR c++
)
FetchContent_MakeAvailable(sparse-vector)

target_link_libraries(your-target PRIVATE Calbona::sparse-vector)
```

Checkout рядом с вашим проектом работает так же, через `add_subdirectory(path/to/sparse-vector/c++)`. Префикс установки также экспортирует пакет CMake, поэтому `find_package(sparse-vector)` тоже работает

**Rust** — обратите внимание, что импортируемый crate — `sparse_vector`, а не имя пакета:

```sh
cargo add sparse-vector-rs
```

В каждом каталоге реализации лежит собственный README с использованием и справочником API для этого языка. Эта страница определяет семантику, общую для всех них, чтобы не повторять её трижды

## Семантика, общая для всех реализаций

### Значение по умолчанию

Вектор создаётся со значением по умолчанию — значением, которое сообщается для любой позиции без явной записи. По умолчанию это `0` типа number, если не задано другое

Значение по умолчанию можно заменить позже. Замена немедленно удаляет все записи, равные новому значению по умолчанию

Поскольку у каждой позиции есть определённое значение, чтение тотально. Любое целое число — сохранённое или нет, лежащее в диапазоне или далеко за его пределами — возвращает значение, а не вызывает ошибку

### Запись, равная значению по умолчанию, никогда не сохраняется

Запись значения по умолчанию в позицию равнозначна удалению того, что там было. Именно это и поддерживает разреженность структуры: память составляет O(k) от числа записей, действительно отличных от значения по умолчанию, — независимо от того, насколько далеко разнесены индексы и насколько отрицательными они становятся

### Отбрасывание выполняется по собственному равенству каждого языка

Запись отбрасывается, когда она сравнивается как равная новому значению по умолчанию, — по обычному равенству самого языка: `===` в TypeScript, `operator==` в C++, `PartialEq` в Rust

Для чисел и строк все три совпадают в точности, включая неудобные случаи:

- `-0.0` равен `0.0`, поэтому сохранённый `-0.0` отбрасывается, когда значение по умолчанию — `0.0`
- `NaN` не равен сам себе, поэтому сохранённый `NaN` остаётся, даже если само значение по умолчанию — `NaN`

В TypeScript `0`, `'0'`, `false` и `null` — четыре значения четырёх разных типов, и отбрасывается только полное совпадение. Статически типизированный вектор может хранить лишь один `T`, так что именно этот набор в C++ и Rust попросту не возникнет, — но правило, которое он иллюстрирует, а именно что равенство точное и без неявных преобразований, действует во всех трёх

А вот для объектов все три действительно расходятся, и это единственное место, где становится видна *тождественность* значения. `===` в TypeScript сравнивает ссылки на объекты, а `operator==` и `PartialEq` обычно структурны. Два различных объекта с одинаковым содержимым — это одно значение в TypeScript и два в C++ и Rust, поэтому запись, содержащую равный, но другой объект, первый сохранит, а двое других отбросят. Когда нужна именно тождественность, заложите её в равенство самого типа: указательный тип даёт это бесплатно — `operator==` у `std::shared_ptr` сравнивает указатели, а `Rc<T>` можно обернуть в newtype, сравнивающий через `Rc::ptr_eq`. В README для C++ и Rust приведён соответствующий рецепт

### Сериализация

Запись — это обычный объект ровно с двумя ключами:

| Ключ | Тип | Смысл |
| --- | --- | --- |
| `index` | целое число | позиция, отрицательная или нет |
| `value` | что угодно | значение, хранимое там |

Вектор сериализуется в одни только свои записи, в порядке возрастания индекса. Значение по умолчанию в эту структуру не входит, поэтому при круговом преобразовании его нужно нести с собой
